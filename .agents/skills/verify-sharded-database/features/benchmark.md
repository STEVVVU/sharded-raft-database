# Real-node benchmark with k6

Version 2 is integrated and awaiting hosted real-product smoke. Version 1 failed fixture setup in run 39730696115 because its fixture exceeded native limits; the raw failure and source history remain retained. No accepted throughput result or product limit change is claimed.

The existing launcher, tools/benchmark.py, owns nine actual nodes, task-specific loopback ports/stores and one k6 v2.3.0 subprocess. tools/benchmark-k6.js drives the real HTTP/Raft protocol with native k6 arrival scheduling, dropped iterations, transaction groups and statistics. tools/benchmark_support.py supplies only owned process/resource capture and evidence persistence. The retired custom load/statistics helper has been removed.

Run 'python -m unittest discover -s tools -p test_*.py -v' and 'node --experimental-vm-modules tools/test_k6_adapter.cjs' for pure adapter/oracle checks. With the real binary built and pinned k6 on PATH, 'python tools/benchmark.py smoke' seeds all 160 bounded keys, drives 50 mixed transactions through eight reusable VUs, checks exact responses, reads back every latest acknowledged key and all 128 immutable read keys, and confirms owned cleanup. This smoke is defined but has not yet been observed on the new integration.

'python tools/benchmark.py benchmark' requires isolated Linux. Version 2 covers 64 / 1,024-byte values, read percentages 100 / 95 / 50 / 0 and 1 / 8 / 32 reused serialized VUs. The 24 cells each run five times at 25 offered transactions/s for ten seconds, reversing order between repeats. Fixtures occupy 39 / 41 / 41 / 39 of the native 64 keys per shard. At most 32 load identities, one seed identity and one final verifier identity occupy 34 of 64 client slots per shard. The write key is disjoint per VU. A write transaction includes PUT plus exact GET readback; report transactions/s and native get / put_get group tails, not bare PUT throughput. See the [full freeze and framework provenance](../../../../docs/benchmarks/k6-v2-plan.md).

Native k6 sweeps offer 5 / 25 / 100 transactions/s with 32 VUs, 64-byte values and 95% reads. Only a zero-drop, zero-error, fully accounted rate with native group p99 below five seconds qualifies for 120-second stability. Sustained SLO failure invalidates the campaign. The native framework does not provide an intended-arrival timestamp for every dropped offer; never invent those timestamps or present started-group tails as desired-arrival tails. Native raw output and all failed, rejected, uncertain, dropped, unresolved and planned-but-not-started counts remain retained.

Two additional traffic cells trigger migration or an owned group-a leader kill after one third of planned starts appears in k6's native output. Committed migration phases and target owner/epoch are checked through settlement. The killed node restarts on its same store. Exact final readback follows both faults, unless an unresolved invocation blocks a durability claim. These are scoped disjoint-key oracles; the existing process/history verifier remains the independent semantic baseline. The workflow gates 'python tools/verify.py' before metric smoke.

Ignored evidence/benchmark-v2-*/ holds the program summary, exact source/dirty state, CPU/RAM/runtime/k6 version and binary hash, workload/input hash, per-node status, native k6 summaries/raw samples, safe synthetic invocation/return receipts, fault phases, node logs and CPU/RSS including k6. The workflow explicitly selects those files; it excludes cluster.json, bearer tokens and all node data directories. k6's file-console logger lacks the normal source field in v2.3.0; the receipt parser and pure control handle that pinned native format. No HTTP debug logging is enabled.

'profile' preserves the existing Go scheduler/GC trace only. Service hot-path CPU profiles and /status commit/applied telemetry are unavailable; collect native profile evidence before product optimization. Fixed four-shard membership precludes shard-count scaling. All processes and observer threads remain task-owned, bounded and cleanup-checked. Evidence survives cleanup.
